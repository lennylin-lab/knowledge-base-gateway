# V1.3 模型控制面路线图

## 1. 版本目标

V1.3 的主题是：**模型控制面**。

V1.1 解决了持久化身份、模型权限、多 Provider 路由、限流、审计和生产可靠性；V1.2 统一了模型协议、工具调用与开发者平台。V1.3 在不破坏既有契约的前提下，把调用方仍在自持的三类模型相关配置统一托管到网关——**embedding 调用、subject 默认模型、RAG 检索阈值（retrieval profile）**——使网关成为模型路由、能力、配额与选型的唯一控制面。

同时，本版本补齐了多上游部署（不同厂商、不同密钥）、多行策略语义、能力错误可诊断性这三类在真实对接中暴露的运维缺口。

本版本不把网关扩展成配置中心或策略引擎：retrieval profile 对网关是不透明 JSON，结构校验归调用方。

## 2. 前置条件与兼容性原则

- V1.2 的 Chat Completions、Responses API、模型发现、能力矩阵、管理查询和契约测试已可用。
- 既有 `/v1/chat/completions` 请求/响应字段、SSE 终止事件、错误 envelope 和 request-id 行为保持冻结。
- `model` 必填语义对老客户端不变：默认模型回填仅在请求**缺失** `model` 字段时生效，显式传 `model` 行为与 V1.2 一致（A/B 与逃生通道）。
- 新增能力均为加法演进：`access_policies` 新列为可空，`model_catalog.retrieval_profile` 为新增 JSONB；不设置时行为与 V1.2 完全一致。
- 客户端仍然只能选择公开模型名；provider 名、上游模型名、URL 和密钥永不暴露。
- 迁移全部为加法（0005：两个可空 FK 列 + 一个 JSONB 列；后续 0006 为 per-provider 凭据支持预留的零迁移设计），回滚路径见各自 `.down.sql`。

## 3. V1.3 范围

### 必须完成

1. 提供 OpenAI 兼容的 `POST /v1/embeddings`，透传上游并按目录声明校验向量宽度。
2. 能力矩阵新增 `embeddings` 与 `embedding_dim`（目录属性；网关将声明维度注入上游 `dimensions`，宁可在宽度不符时失败也不静默返回错宽度向量）。
3. `access_policies` 增加 `default_model` / `default_embedding_model` 两个可空槽位，请求缺 `model` 时按 kind 回填；回填后的模型仍须在 subject 授权内。
4. `model_catalog.retrieval_profile`（模型级 JSONB）随 `GET /v1/models/{model}` 下发，内容对网关不透明。
5. Provider 凭据支持按 provider 注入（`<KIND>_API_KEY__<PROVIDER_NAME>`），缺省回退 kind 级环境变量——支撑 chat 与 embeddings 分属不同厂商的多上游部署。
6. 多行 subject 策略语义定案并实现：`default_*` 折叠为 first-non-empty-wins；配额上限折叠为 **min-of-declared**（各字段取最严值），并提供生效视图。
7. 能力门控错误自描述：`capability_not_supported` 的消息命名缺失的能力键与协议（envelope 形状不变）。
8. 权威能力参考 `docs/capabilities.md`：全部能力键、默认值、门控面与新特性扩展协议。

### 暂不完成

- 按模型独立配额（per-model quota）：仅预留 `policy.Resolver.LimitsFor(subject, publicModel)` 组合点，不做行为变更。
- retrieval profile 的管理端变更接口：本期属 catalog 数据，由 SQL/迁移工具维护。
- `vision` / `reasoning` 的请求面（能力键保留，扩展协议覆盖未来接入）。
- subject 级独立上限表（#8 决策的中期方向，本期由 min 折叠覆盖）。

## 4. 公共 HTTP 协议

### 4.1 Embeddings API

新增：`POST /v1/embeddings`。

请求字段：`model`、`input`（字符串或字符串数组，统一按批处理）。客户端传入的 `dimensions` 不生效——实际维度由目录 `embedding_dim` 声明并注入上游。

响应为标准 OpenAI embeddings 形状：`object: "list"`、`data[].embedding`、`usage`、`model`。上游返回宽度与声明不符时返回 500 `embedding_dim_mismatch`（宁可失败也不静默返回错宽度向量）。

Embedding 的 token 与 chat 同一个 subject 日/月配额池；usage 已知按实际结算，未知保守预扣。回滚开关：`GATEWAY_EMBEDDINGS_ENABLED=false` 单独关闭该端点。

### 4.2 模型发现扩展

`GET /v1/models/{model}` 在既有 `capabilities` 之外新增 `retrieval_profile`（原样透出的不透明 JSON）与 `config_version`。该接口仍只返回当前 subject 有权使用的模型；模型不可用统一 403 `model_not_allowed`。

### 4.3 默认模型回填

无 `model` 字段的请求按 kind 回填 subject 的 `default_model`（chat/responses）或 `default_embedding_model`（embeddings）。多行 subject 时按 first-non-empty-wins 折叠，且任一行声明即生效（不因其他行槽位为空而失效）。若回填后模型不在授权内，仍然 403。

## 5. 策略语义（多行 subject）

- `default_model` / `default_embedding_model`：first-non-empty-wins。
- 配额上限（`rate_per_minute` / `max_concurrent` / `daily_tokens` / `monthly_tokens` / `max_input_tokens` / `max_output_tokens`）：**min-of-declared**——subject 的实际上限是所有授予的交集，新增一行不可能变相抬高配额。
- 折叠逻辑集中在 `policy.FoldPolicyRow` / `Resolver.LimitsFor`（后者同时是未来 per-model 配额的唯一组合点），pg 与内存模式共用；单行 subject 恒等。
- 管理端：`POST /admin/policies/{subject}/default-model`（kind: chat/embedding），原子事务 + 管理审计，热生效；`GET /admin/policies` 视图暴露折叠结果。

## 6. Provider 凭据

- 凭据解析按 provider 优先：`<KIND>_API_KEY__<PROVIDER_NAME>`（provider 名大写化、非字母数字映射为 `_`）命中时优先，缺省回退 `<KIND>_API_KEY`。
- 零迁移、零契约变化：未设置 per-provider 变量的部署行为与之前完全一致。
- 启动校验语义不变：两级都缺失时拒绝启动，错误只点名所查变量，绝不含值。

## 7. 能力隔离与错误

- 一切特性必须声明在能力矩阵上，在触碰 provider 之前拒绝；不支持的能力返回 400 `capability_not_supported`，且消息命名缺失的键与协议：
  `model does not declare capability '<name>' (protocol <protocol>)`。
- 扩展协议（新特性接入的六步）见 `docs/capabilities.md`；`vision` / `reasoning` 为保留键，`retrieval_profile` 为目录属性而非请求特性。
- 详见 `docs/capabilities.md`（本版本的权威参考）。

## 8. 升级与验收

升级顺序与 V1.2 一致：先迁移（`go run ./cmd/migrate up`，应显示 version 5, dirty=false），再重建网关进程。

验收清单（完整版见调用方对接文档，如 `knowledge-base-server` 仓库 `docs/gateway-v1.3-integration.md`）：

- 迁移版本与 healthz/readyz；
- 目标模型能力声明与 `/v1/models/{model}` 一致（含 `embeddings` / `embedding_dim`）；
- `/v1/embeddings` 返回声明宽度向量；人为维度不一致触发 500 并恢复；
- 默认槽位设置后，无 `model` 请求的审计记录回填后的模型；
- `retrieval_profile` 与 catalog 一致、调用方启动日志标注取值来源；
- 多行 subject 下调低任一行配额，全部模型请求按 min 生效（429 + `Retry-After`），恢复后正常。

## 9. 实施顺序

1. 迁移 0005 与默认模型槽位、retrieval profile 下发。
2. Embeddings 端点、能力声明注入与宽度校验。
3. 多行策略折叠（#7 回填修复、#8 min-of-declared）。
4. Per-provider 凭据（#5）。
5. 能力错误自描述与 `docs/capabilities.md`（#4 Feature 4 收尾）。
